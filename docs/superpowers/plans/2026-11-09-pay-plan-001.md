# PAY-PLAN-001 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Centralizar na API os planos, limites, permissoes e restricoes do Controle Ja, fazendo o Flutter apenas consumir e apresentar o contrato canonico.

**Architecture:** Evoluir o `EntitlementService` existente para resolver o plano efetivo e expor limites/permissoes. Um estado de entitlement por usuario com `@Version` serializa mutacoes limitadas; um reconciliador marca `planRestricted` de forma deterministica. Os services de dominio continuam donos de suas mutacoes e chamam guards pequenos e compartilhados. O Flutter usa o endpoint canonico, cacheia apenas para apresentacao e respeita os indicadores retornados pelos recursos.

**Tech Stack:** Java 17, Spring Boot, JPA/Hibernate, Flyway, PostgreSQL/Testcontainers, Flutter, Riverpod, SharedPreferences, JUnit/RestAssured e flutter_test.

**Spec:** Trello PAY-PLAN-001: https://trello.com/c/5p8nNbXW; GitHub API #36; GitHub mobile #25.

## Global Constraints

- API e a unica autoridade; nenhuma regra critica depende do Flutter.
- Preservar historico, saldos, faturas e transacoes; downgrade nunca exclui dados.
- `planRestricted` nao substitui `enabled` ou `deletedAt`.
- Nao implementar Billing, compras, anuncios, paywall ou precos.
- Nao usar `ALL`, e-mail/allowlist ou estado local como atalho para plano.
- Alteracoes em banco somente por migration Flyway, com backfill seguro.
- Aplicar TDD: criar/ajustar teste, comprovar falha, implementar o minimo e comprovar sucesso.
- Nao tocar na arvore suja atual de `controleja-knowledge`; usar worktree limpa baseada em `dev` para documentacao.

## Review Focus

- Contagem exata por recurso e exclusao correta de defaults/conta espelho.
- Downgrade e upgrade deterministas por `createdAt ASC, id ASC`.
- Bloqueio de mutacoes indiretas com itens restritos.
- Concorrencia real: duas criacoes no ultimo slot nao podem ambas confirmar.
- Compatibilidade de login/auto-login e defaults restritivos no Flutter.
- Nenhuma regressao em saldo, cartao/fatura, categoria tecnica ou veiculo historico.
